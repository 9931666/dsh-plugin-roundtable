# RoundTable v0.2.21

**宿主兼容性复核版**：把 v0.2.2 的兼容基线从 DSH 0.1.2-rc.1 推进到 **0.1.5-rc.1**，并修掉两处"能跑但不真实"的隐性契约问题。

## 为什么需要本版

v0.2.1/v0.2.2 的 `peerDependencies` 全部停在 `^0.1.2-rc.1`。插件在本机之所以仍然工作，只是因为 profile 里装的是 `link:` 本地目录 + `node_modules/@deepseek-ai/*` 直指 0.1.5-rc.2 的 junction——**这条路径绕过了 peer 依赖解析**。真实用户在 0.1.5 宿主上全新安装时，npm 7+ 会因 peer 范围冲突直接报错。换言之：本机"能跑"掩盖了分发路径的断裂。

## 变更

### A 兼容基线推进到 0.1.5-rc.1
- **A1 版本号 0.2.2 → 0.2.21**（`package.json`）。
- **A2 `peerDependencies` 全部 `^0.1.2-rc.1` → `^0.1.5-rc.1`**；`devDependencies` 升到实测的 `0.1.5-rc.2`（宿主本体 `dsh` 为 0.1.5-rc.1，`@deepseek-ai/*` 各包为 0.1.5-rc.2）。
- **A3** README（安装要求 / 升级说明 / 版本徽章）与 `roundtable_*` 的 usage 文案同步改为 0.1.5-rc.1。

### B 0.1.2-rc.1 → 0.1.5 契约复核结论
逐项核对后**未发现破坏性 API 变更**，以下均已按 0.1.5-rc.2 实体类型验证：
- 16 个 `peerDependencies` 包**全部存在**，无被删除/合并/改名者；`ui-slots` 之外无新缺包。
- `ctx.subagents` 四个 API 签名一致：`getProvider` / `list` / `startContinuable` / `sendMessage(sender, targetId, content, { signal })` / `interrupt(id, { kind, agent })`。
- `ctx.tools.register`、`ctx.systemPrompt.section`、`ctx.settings.register`、`ctx.llm.*`、`ctx.webServer.register`、`ctx.userQuestions.ask`、`ctx.workspaceRegistry` 均未变。
- 客户端 slot 键 `conversation.view`、`settings.section` **都还在**；0.1.5 官方示例的注册写法与插件一致（`ctx.slots.inject(key, () => ctx.slots.register({ name, id, order, label }, Component))`）。
- 插件清单契约未变：`dsh.client.platform` + `exports["./client"]` 仍需，插件已满足；`cordis.patch.yml` 仍是顶层数组 `{ insert: [...] }`。

### C 修掉两处隐性契约问题
- **C1 `connection.rpc.handle` 过时第三参**（`src/rpc.ts`）：0.1.1 时代的 `handle(channel, handler, { authority: 'trusted-host' })` 实际调用早已是两参，却留着旧签名 shim 与"必须传 authority 否则通道挂不上"的注释。0.1.5 真实签名为 `handle(channel, handler) => disposer`，多余实参被运行时静默忽略——正因如此它一直没被发现。现已删掉 shim 选项与该实参，并把历史故障模式改记为注释（不再误导后人）。
- **C2 类型锚文件不再遮蔽宿主真实服务面**（`src/client/ui-slots-anchor.d.ts`）：
  - v0.2.2 手写的两成员 `RoundTableSlotsService` **在接口合并中胜出**，遮蔽了宿主真实的 `SlotRegistry`，导致 `ctx.slots.entries / getVersion / subscribe / spec / snapshot / onEntryError` 全部不可见（实测：`ctx.slots` 解析结果就是本地那个手写类型）。
  - v0.2.21 改为**成员级精确镜像**宿主 `SlotRegistry`（0.1.5-rc.2），遮蔽消除，服务面恢复完整。
  - **关键约束（已写入文件头注释）**：该文件必须保持"全局脚本"（零顶层 `import`/`export`）。一旦加入 `import`，其中的 `declare module '@deepseek-ai/dsh-client-ui-slots'` 会从「环境模块声明」退化为「模块增强」，立即报 `TS2664`——并且会连带打断 `locales.ts` 的 `LocaleNamespaceMap` 合并（实测复现）。这是**无法改为 `import type { SlotRegistry }`** 的原因。

## 验证

- `tsc` host + client **双端全绿**。
- `tsdown` 构建通过，产出 `lib/index.js` + `lib/client.js` + 完整 `lib/types/**`；产物内已确认为 v0.2.21 文案、`authority` 字符串与旧版本字符串均已消失。
- 全量扫描 223 个宿主包：`roundtable_*` 工具名**无一命中**，确认工具集由本插件提供、插件在 0.1.5 宿主内正常加载。
- 客户端 bundle 的运行时 `require` 仅依赖 `react` / `react/jsx-runtime`（宿主模块由 `dsh.client.inject` 静态种子提供），无悬空引用。

## 已知限制

- **`SlotRegistry['register']` 在所有消费者侧都是 `any`**：宿主将其声明为 `SlotCore['register']`，而 `SlotCore` 所在的 `@deepseek-ai/dsh-client-ui-slots` 从未发布（node_modules、`.pnpm`、package-lock 中均不存在，仅作为 `dsh-client-ui-renderer` 的 devDependency 类型锚与 web shell 种子词存在）。这是宿主侧缺口，插件无法从自身闭合；锚文件中保留的是**按宿主运行时 `_register(options, component)` 实测**得到的精确签名。
- 历史会议记录（`.roundtable/`）跨大版本兼容性不保证，重要会议请先导出。
- 与 v0.2.1 相同的其余限制不变。
