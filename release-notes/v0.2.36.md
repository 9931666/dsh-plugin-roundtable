# RoundTable v0.2.36

**对齐宿主 0.1.5-rc.2，并修掉"界面整个不出现"这一类故障：把两个可选能力从 load-gating 的 `inject` 里摘出来，给两个界面入口包上渲染错误边界，并把这条不变量钉成产物级测试。**

> 起点：用户反馈「Bug 有点多，目前无法调用界面」。本版先做**宿主版本体检**，再按可复现证据修，不做无证据的重写。

## 1. 修复：`inject` 把可选能力当必需，缺一个就整个插件不加载（"无法调用界面"的根因）

**机制**（cordis 4.0.2 实测）：`inject` 的类型是 `string[] | 拦截配置对象`——**没有"可选注入"这种形式**，对象形式只是 per-service 拦截配置。因此 `inject` 里列出的每个服务都是**加载门禁**：只要有一个缺失，整个插件 fiber 停在 `PENDING`，于是 `roundtable_*` 工具、`/plugins/dsh-plugin-roundtable/*` 路由、Web GUI 的「圆桌会议」页签与设置页**一起消失**，而且**没有任何报错**——用户看到的就是"界面调不出来"。

**两处误用**：

| 位置 | 原值 | 问题 |
| --- | --- | --- |
| 宿主 `src/index.ts` | `['tools','subagents','agents','systemPrompt','userQuestions','skills']` | `skills` / `userQuestions` 都是**可选能力**，插件本来就用 `ctx.get(...)` 可选读取。`skills.ts` 的模块注释把这点写成硬约束 #1：*"插件可以在没有挂载 skill 服务的 profile 里加载……绝不让插件加载失败"*——`inject` 却让它必然加载失败。 |
| 浏览器 `src/client/index.ts` | `['slots','locale','connection']` | `connection` 只是 RPC 的**兜底传输**（注释自己写着"OPTIONAL fallback"）。列进 `inject` 后，缺少该服务的组合里页签与设置页**一个都不注册**。 |

**修法**：

- 宿主 `inject` 收敛为真正离开它就工作不了的四个：`['tools','subagents','agents','systemPrompt']`；可选能力继续走 `ctx.get(...)`（`skillRegistryOf()`、`userQuestions === undefined` 兜底分支原样保留，终于可达）。
- 浏览器 `inject` 收敛为 `['slots','locale']`；`connection` 改为运行时可选读取。注意 cordis 的 Context 代理在**没有 inject 时直接抛错**（`cannot get property "connection" without inject`），所以不能用属性访问——已改用 `ctx.get('connection')`（非严格，缺失返回 `undefined`）。

## 2. 修复：渲染崩溃被宿主静默摘掉，故障无迹可查

DSH 对渲染抛错的 slot 条目会做隔离（`onEntryError` + 条目退役）——隔离本身是对的，但对用户来说「圆桌会议」页签**就那么不见了**，没有任何提示。这正是"界面调不出来"这类反馈无法定位的原因。

**修法**：新增 `src/client/slot-boundary.tsx`，把两个入口（`conversation.view` 与 `settings.section`）都包进一个类组件错误边界：

- 崩溃时渲染一块**可读报错面板**（错误名 + 消息 + 反馈指引），不再无声消失；
- 同时 `console.error` 打出完整组件栈，方便直接贴 issue；
- 边界自身不渲染任何数据，不会成为第二个故障源；正常路径完全透明（原组件照旧收到 owner props + 标准席位 + inject face）。

## 3. 质量门禁：把这条不变量钉成产物级测试

新增 `test/inject.test.mjs`（零依赖，3 例），断言的是**构建产物 `lib/`**而不是源码——理由同 `version.test.mjs`：profile 是 `link:` 挂载，真正被加载的是 `lib/`，源绿而产物说谎的坑本项目已经踩过一次。

1. 宿主 `lib/index.js` 的 `inject` 不含 `skills` / `userQuestions`，且含四个必需服务；
2. 浏览器 `lib/client.js` 的 `inject` 不含 `connection`，并且**在一个没有 connection 服务的宿主形状 ctx 上**调用 `apply()` 时，仍必须注册两个界面入口（标签可解析、inject face 带 `rpc`/`t`）；
3. 两个入口的组件都必须被错误边界包裹（`displayName` 以 `RoundTableBoundary(` 开头）。

> 这三条断言在旧产物上**必然失败**（旧 `lib/client.js` 导出的 `inject` 实测是 `["slots","locale","connection"]`），因此它们是真正防回归的闸门，不是同义反复。
