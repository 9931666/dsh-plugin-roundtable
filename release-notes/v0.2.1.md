# RoundTable v0.2.1

适配 **DeepSeek Harness 0.1.2-rc.1**（Cordis 4.0.2 / dsh 客户端架构重构）的兼容性版本。

## 为什么需要本版

宿主从 `0.1.1-rc.2` 升到 `0.1.2-rc.1` 后发生破坏性变更，旧版 RoundTable 无法在新宿主上正确加载：

- 客户端运行时三个包被合并/移除：`dsh-client-runtime`、`dsh-client-ui-slots`、`dsh-client-ui-primitives` 不再发布，客户端 `Context` 类型统一改由 `@deepseek-ai/cordis` 提供，插槽注册面并入 `dsh-client-ui-renderer`。
- 宿主 `dsh-settings` 的 `settingsNamespace()` 运行时函数被移除，命名空间改为纯类型（`SettingsNamespace`）。
- 宿主 `ctx.subagents` 的 `followup()` 更名为 `sendMessage()`（签名基本不变）。
- 各官方包版本号整体升至 `0.1.2-rc.1` / `cordis 4.0.2` / `schemastery 3.18.2`。

## 变更

- **适配 API**：`settingsNamespace('roundtable')` → 命名空间字面量；`subagents.followup(...)` → `subagents.sendMessage(...)`；客户端 `ClientContext` → cordis `Context`。
- **类型锚 shim**（`src/client/ui-slots-anchor.d.ts`）：0.1.2-rc.1 发布物中 `@deepseek-ai/dsh-client-ui-slots` 仍是各 client 包 module-augmentation 的类型锚，但包体已并入 `dsh-client-ui-renderer` 不再发布——新增本地声明使类型合并重新生效，并补齐缺失的 `ctx.effect`/`ctx.slots` 类型。
- **依赖清单**：peer/devDependencies 升到 `0.1.2-rc.1` 系；移除已不存在的 `dsh-client-runtime`、`dsh-client-ui-slots`、`dsh-client-ui-primitives`；`dsh.client.inject` 换成现有包（含 `dsh-client-ui-renderer`）；client bundle externals 同步清理。
- 包版本号 `0.2.0` → `0.2.1`。

## 验证

- `tsc` host + client 双端类型检查通过；`tsdown` 双产物构建通过（host 98 kB / client 472 kB）。
- 在 0.1.2-rc.1 宿主机内冒烟：`lib/index.js` 正常加载导出；host 侧 `tools / subagents / agents / systemPrompt / userQuestions / settings / webServer / connection.rpc.handle` 全部可用，插件的注入与 `/roundtable` 通道注册机制有效。

## 安装

```sh
dsh plugin --profile web add @huanlin/dsh-plugin-roundtable
```

或从源码：`git clone https://github.com/9931666/dsh-plugin-roundtable && cd dsh-plugin-roundtable && pnpm install && pnpm build && dsh plugin --profile web add .`

安装后**重启 DSH**、刷新 Web UI。

## 已知限制

- 仅适配 0.1.2-rc.1；回到 0.1.1-rc.2 宿主需用 v0.2.0。
- 其余已知限制与 v0.2.0 相同（第三方模型需显式指定 provider/model；多进程并发写同一会议不保证一致）。
