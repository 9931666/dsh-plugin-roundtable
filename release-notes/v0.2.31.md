# RoundTable v0.2.31

**设置卡片 + DSH 原生 skill 接入**：把"模型自行拍会议参数"这一步换成**用户先确认草案**，并把宿主已有的 skill 能力接进会议（会议可选 skill、可在设置里切换传递方式）。

## 为什么需要本版

在此之前，说一句"开个圆桌会议讨论 X"，主持人就直接调 `roundtable_create` 建会，专家名单、模式、预算全由模型自己拍。用户只能在**会后**通过 UI 改专家，参数甚至无从修改。本版把确认环节前置：**先出草案卡片 → 用户确认或初次修改 → 按确认结果建会**。

同时，DSH 宿主本身已有完整的 skill 体系（`ctx.skills` + 模型工具 `skill`，目录发现由 `dsh-skill-filesystem` 负责）。本版把它接进会议，但**不自己造导入机制**：按官方目录放文件即被识别。

## R1 会议设置确认卡片

- **新增 `roundtable_plan_meeting`（不创建会议）**：接收议题、专家名单与各项参数，推导出一份草案，渲染为可读 Markdown，通过原生 `userQuestions.ask()` 以 `intent.kind='plan-review'` 弹出并**阻塞等待**用户答复。
  - 返回 `decision="approved"`：主持人按这些值调 `roundtable_create` 创建。
  - 返回 `decision="revise"` + 用户原话：主持人更新草案（未改动的项保持不变）后**再次**调用本工具，卡片以 `revised=true` 标注"已按你的意见更新"。
  - 返回 `decision="unavailable"`（服务缺失/被中止）：主持人改为**文字**陈述草案取得同意，仍不放行"自行拍参数"。
- **卡片内容**：会议名称、协作模式、轮数上限、Token 预算、知识库路径、选中 skill、skill 传递方式、逐个专家（`key` — 角色 — 路由）、当前可选 skill 清单、议题目标。
- **"可改全部"的实现口径**：原生 `ask` **没有表单能力**（只有选项列表 + 一个自由文本 `custom`），因此"可改全部"是**自由文本 + 回流重建**，而非富表单；卡片里不塞任何伪交互说明。点选式编辑面板仍属后续版本。
- **默认值优先级**（与既有设置页保持一致）：会议参数显式传入 > 插件 `PreferenceSchema`（设置页）> 插件 `Config` 默认值。`getPlannedDefaults` 注入设置页那一层，**实时读取**。
- **`roundtable_create` 扩展**：新增 `kb_path` / `skills` / `skill_delivery` 三个参数，创建时一并落库；输出回显全部生效值，便于事后核对。
- **`roundtable_status` 扩展**：新增 `skills` 与 `skill_delivery` 字段。

## R2 DSH 原生 skill 接入

- **新增 `src/skills.ts`**：只通过 `ctx.get('skills')` **可选**读取清单与正文（`list({cwd})` / `get(name, {cwd})`）。服务缺失、发现失败、工作区不可读一律降级为空清单——**绝不因为 skill 服务缺席而让插件加载失败**。
- **会议选中 skill**：`Meeting` 新增可选字段 `skills?: string[]` 与 `skillDelivery?: SkillDelivery`，由卡片确认结果写入；`snapshot.ts` / `rpc.ts` / `client/wire.ts` 三处同步透传，前端右栏新增「已选 skill」面板（含传递方式标注）。
- **传递方式 = 设置项（D5）**：`PreferenceSchema` 新增 `skillDelivery: 'relay' | 'direct'`（默认 `relay`），设置页给出两选一 + 各一句话说明：
  - **主持人中转**：主持人读取 skill 正文后按需转交专家 —— 省 token、行为可预测。
  - **专家直接调用**：专家自己用原生 `skill` 工具加载 —— 更自主，但每个专家都会各自读取一遍。
  - 选择在建会时**固化到会议**，`add_node` 时以会议值为准（会议未记录时回退到设置页默认值）。
- **两种模式的实现要点**：
  - `relay`：不改 `toolFilter`，与既有知识库中转同构。
  - `direct`：`nodeToolRestriction('direct')` 返回 `{ allow: 专家白名单, deny: 主持人专属工具 }`，从而放行宿主的 `skill` 工具。`allow` 的语义是 **keep-only**，因此白名单必须列全专家真正需要的工具（文件/搜索/shell/会话管理/协作通道/`skill`）；一旦宿主改名，失败方向是"专家失去该能力"，**不会**顺带放开权限。`deny` 保留作双重保险。
  - `nodePersona()` 注入 skill 段落：列出选中的 skill 名称与使用方式；`direct` 模式下还必须告知清单（`skill` 工具本身不带白名单参数），并**依据宿主是否真的注册了 `skill` 工具**（`ctx.tools.get('skill', captain)`）决定是否让专家去调用它。
- **依赖**：`package.json` 新增 `@deepseek-ai/dsh-skill`（peer + dev，均 optional）；插件 `inject` 增补 `skills`，并加 `import type {} from '@deepseek-ai/dsh-skill'` 以取得 `ctx.skills` 的类型可见性。

## 已知限制

- **卡片是选项列表 + 自由文本框，不是富表单**：原生 `userQuestions` 的结构决定了这一点（见 R1）。想点选增删专家，需要后续版本的 UI 编辑面板。
- **`direct` 模式下无法硬限制**：原生 `skill` 工具不带白名单参数，专家技术上可以加载未被会议选中的 skill；本版的做法是**只告知选中清单、不做硬限制**（persona 中亦如实说明）。
- **会议中途不能改 skill 清单**：清单在创建时固化；新增资料请走 `relay` 路径。
- **卡片渲染取决于 Web UI 是否识别 `plan-review` intent**：不识别时退回普通选项列表，**功能不受影响**，答复编码（`selected` 含 `批准` 标签即视为批准）完全一致。

## 升级提示

改的是 **host 侧**：装好/构建后需要**重启 DSH**（客户端改动刷新页面即可）。历史会议记录（`.roundtable/`）为向后兼容的可选字段扩展，旧会议无 `skills` 字段时按"未选 + `relay`"处理。
