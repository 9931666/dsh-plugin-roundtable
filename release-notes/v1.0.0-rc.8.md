# v1.0.0-rc.8 — 启动前确认卡表格化 + 专家提示词

本版只改「开会前那张确认卡」与专家的提示词入口，不改会议协议、不改进程/拓扑语义、不改数据格式（老会议可直接打开）。

## 确认卡：从列表改成两张表

此前卡片是「- 字段：值」的逐行列表，专家只有 key / 角色 / 路由三样。现在固定为两张 Markdown 表：

- **表 1 会议设置**：会议名称、协作模式、轮数上限、Token 预算、知识库、选中 skill、skill 传递方式、专家数量。
- **表 2 专家名单**：`# / 专家 key / 角色 / 模型 / 提示词` 五列，一眼能横向对照。

配套细节：

- **继承路由显示具体模型**：专家没写 `provider/model` 时，卡片显示「继承主持人（deepseek/…）」而不是只有「继承主持人」——用户看得到继承的到底是哪个模型。
- **提示词摘要**：有值时显示前 40 字（只有真被截断才补「…」），没值时写「自动（总纲 + 角色）」，不假装有内容。
- **单元格转义**：值里的裸 `|` 与换行会被转义/压平，表不会错列。
- **修改回显**：再次弹卡时，标题标「（已按你的意见更新）」，顶部列出「本次变更」；主持人没给变更点就如实写「（本次未标注具体变更）」，不假装有改动。

## 专家提示词真正生效

- `roundtable_plan_meeting` 的 `experts[]` 新增 `prompt`（可选），确认后由主持人原样传给 `roundtable_add_node` 的新参数 `prompt`。
- 该提示词写入 `MeetingNode.expertPrompt`，由 `nodePersona()` 生成「专家补充定位」段。
- **硬边界**：它只放宽这位专家的专长范围/关注点；不能放宽《全局协作总纲》的红线（发言格式、严禁编造、不替用户拍板），冲突部分视为无效。这样确认卡不会变成绕过红线的后门。
- 未填提示词时 persona 与旧版**逐字一致**（不多空行），老记录不受影响。

## 按钮文案

- 统一为「**确定开始**」/「**仍需修改**」，与针锋的确认卡保持同一套说法。

## 兼容性

- 不传 `prompt` / `changes` 时行为与 rc.7 一致。
- `formatMeetingDraft` 的签名变为 `(draft, options)`，`experts` 移入 `MeetingDraft`；全仓仅工具层与测试使用，client 未引用。
- Web UI 右栏「添加专家」的 user-action 暂不含 `prompt` 字段（下一版再补）。
