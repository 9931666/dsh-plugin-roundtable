# RoundTable v0.2.35

**账目干净、边界可守、常用动作顺滑：清掉一处真实的数据一致性隐患与三处"设计承诺 vs 代码现实"的不一致，补上最小质量门禁，并做掉两个高频缺口——用户自建角色预设与整场会议导出。**

> 版本号说明：本轮任务书原命名为 `v0.3.0`，最终按用户决定定版为 **v0.2.35**（改动性质是"收账 + 两个补齐"，不是架构级跃迁）。

---

## 1. 修复：`user-actions` 清空的非原子性（A2，真实数据一致性隐患）

**问题链**：`clearUserActions()` 原先是「先读计数 → 直接 `writeFile(file, '')` 截断」，非原子。UI 的追加（`roundtable/user-actions.append`）与主持人的清空（`roundtable_actions_clear`）是两条独立路径：清空瞬间恰逢 UI 正在追加、或进程写一半崩溃，就可能留下**半行 JSON**；而读取侧对坏行是**静默跳过**——那条用户操作永久消失，且没人知道。

**修法**：

- `src/state.ts` 新增通用 **`writeTextAtomic(file, text)`**（同目录 tmp + rename；rename 失败时把 tmp 改名为 `.stale-<uuid>` 而不是留脏文件），`writeJsonAtomic` 改为复用它。
- 新增 `readUserActionsReport()`：区分「可用 action 列表」与「`malformed` 坏行数」。
- `appendUserAction()` 与 `clearUserActions()` 共用一把串行锁（`user-actions:<stateRoot>:<meetingId>`），**追加与清空不再可能交错**。
- `clearUserActions()` 返回 `{ cleared, malformed }`，`roundtable_actions_clear` 的输出 schema、描述与渲染文案同步升级：`malformed > 0` 时明确提示主持人**必须向用户说明这些操作已丢失**。
- 顺手把同构的 `clearFeedback()` / `clearFeedbackForMeeting()` 也切到原子写（同一类隐患，同一处修法）。

## 2. 清账：三处"定义了却没人用"的不一致（A5）

| 项 | 原状 | 处理 |
| --- | --- | --- |

## 3. 新增：用户自建角色预设（B3）

- **偏好字段** `rolePresets: RolePreset[]`（`id / name / role / provider? / model?`，默认 `[]`）。**不预置任何内置角色**，列表空着等用户自己建。
- **校验手写在 RPC 侧**（`sanitizeRolePresets`）：因为实测 schemastery 的 `z.object` 在 resolve 阶段**不校验缺失的 required 字段**（`s({ rolePresets: [{ id: 'a' }] })` 直接通过），所以 schema 拦不住脏数据。规则：`name` + `role` 非空是硬要求；`id` 缺失或重复时**重新分配**（保数据，不静默丢条目）；`provider`/`model` 必须成对，半对视为"继承主持人"；单字段超长截断、总数超 50 截断。
- **设置页**（设置 → 圆桌会议 → 「角色预设」）：列表（名称/角色说明/模型）+ **新建 / 编辑 / 删除**，模型下拉复用既有 `roundtable/models.list`。预设的增删改**立即落库**（提交完整偏好对象，与底部「保存」语义一致），不用等按保存。
- **专家管理面板**：表单顶部新增「角色预设」下拉，选中即填充 `role` / `provider` / `model`（专家 key 仍由用户填）。仍走既有链路——写 `user-actions.jsonl` 的 `add-node` → 主持人下一轮 `roundtable_add_node`，**不新增任何链路**。预设为空时给出"去设置页新建"的指引。
- 三处类型同步：`src/types.ts`（`RolePreset`）、`src/rpc.ts`（`RoundTablePreferences`）、`src/client/wire.ts`（`RoundTablePrefs.rolePresets`）。

## 4. 新增：整场会议导出为 Markdown（B6）

新增主持人专属工具 **`roundtable_export_meeting`**（同时加入 `members.ts` 的 `NODE_DENIED_TOOLS`，专家不可调用）：

- 头部：插件版本、会议 id/名称、协作模式、状态、创建时间、结束时间、预算用量、知识库、选中 skill；
- 议题 / 目标；专家名单（key / 角色 / provider / model / reasoning effort / 状态）；决策记录（问题 / 选项 / 用户选择 / 自定义答案 / 状态 / 时间）；
- 发言记录：**按轮次分组**，标注 `发言者 → 受众` 与时间戳，非 speech 类型标注 kind，单条超 4000 字符截断并标注原长；
- 评审结论（存在 `review.json` 时内联完整的针锋相对记录）；
- 用户调整记录（`user-actions.jsonl`），并注明"只包含尚未被清空的记录"。
- **不新增状态**：全部读自既有文件。会议进行中也能导出，头部标注**「进行中快照」**。
- 除返回 Markdown 外，**同时写入 `<meetingDir>/export.md`**（`save: false` 可只取文本），便于用户直接打开文件。

顺带重构：把评审导出拆成 `renderReviewMarkdown`（头部）+ `renderReviewBody`（主体），整场导出复用主体，避免两份重复的 issue 头部。

## 5. 新增：知识库摘要缓存（C2，省 token）

- 会议级缓存文件 `<meetingDir>/kb-digest.json`：条目 `{ path, size, mtimeMs, digest, ts }`。
- **失效键 = `path + size + mtimeMs`**：宿主 `listKbDirectory()` 本来就在 `stat` 每个条目，比对不产生额外 IO。
- 新增主持人工具 **`roundtable_kb_digest`**（相对路径按会议 `kb_path` 解析；插件自己 `stat` 出 `size`/`mtimeMs`，主持人不必也不该手填这两个数）；同 `path` 覆盖，超 50 条按最旧淘汰，单条摘要超 2000 字符截断。
- `roundtable_status` 新增 **KB digest cache** 段：把每条缓存用磁盘现状标注为 **`[HIT]`**（键未变，直接用摘要）或 **`[STALE]`**（文件变了，必须重读），并给出条目数与有效数。缓存**不参与预算计数**——它不消耗模型 token。
- `usageSectionText` 第 10 条改写为完整协议：**读文件前先看缓存；HIT 就直接复用、不要再读**（"主持人读一遍 + 专家读一遍"正是双倍 cost 的来源）；未命中才读，读后用 `roundtable_kb_digest` 写回。

> 与任务书的一处偏离：R6.2 原本要求"新增 RPC 端点（读写）"。本轮**没有加这两个 RPC 端点**——当前 UI 没有任何消费者，加了就是新的"定义了却没人用"的代码，正是 A5 刚清掉的那种账。主持人侧的可达路径由 `roundtable_status`（读）+ `roundtable_kb_digest`（写）承担，两者都是真实调用点。

- 7 个测试文件、**56 个用例**，覆盖：

## 7. 顺带修掉一个此前无人体检到的缺陷：导出头部版本号说谎

`renderReviewMarkdown` 的导出头部**硬编码** `@huanlin/dsh-plugin-roundtable v0.2.21`，而 `package.json` 已经走到 0.2.32——**导出物里的版本号是错的，且没有任何测试会发现**。

- 新增 `src/version.ts` 作为源码侧单一来源：`PLUGIN_VERSION = '0.2.35'`、`PLUGIN_ID`、`HARNESS_RANGE`。

## 8. 收尾追加：两处无争议加固（针锋相对评审搁置后）

原计划对 v0.2.36 范围方案做一轮「针锋相对」红队评审，因模型额度耗尽，在第一位专家完成发言后搁置（其观点已留档于会议目录的 `transcript.jsonl`）。搁置前只落地了两项**明确无争议**的小改动：

- **A3 收敛：`appendUtterance` 加串行锁**。`transcript.jsonl` 的追加原先无锁——`O_APPEND` 对单行小写入本身是原子的，但长行或生命周期事件竞态下仍有交错窗口。现在一次发言与追加共用一把会议级锁（`transcript:<stateRoot>:<meetingId>`），两条发言不可能写进彼此中间。
- **预算口径诚实化（P1 的保守处理）**。`usedTokens` 只累加**发言文本**的粗估（≈0.6 token/字），不含 system prompt、专家 persona、历史上下文与工具调用开销——它**不是真实账单**。此前 UI 与 `roundtable_status` 都把它直接标成 "token"，等于让用户误以为那是花费。现在：
  - `roundtable_status` 的预算行明确标注 `(spoken-text estimate only — NOT the real LLM spend)`；
  - usage 第 8 条加入 HONESTY RULE，要求主持人在向用户报告时说明这一口径；
  - README「预算熔断」条目同样标注。

> **未决（留给下一轮，需要先讨论再动）**：预算口径的**根本修法**（接宿主真实 usage 回调，还是改 UI 语义）、N3（预设承载 per-expert 预算 + persona 补充指令——红队已指出属职责越界）、N4（会议归档，红队指出 `archived` 与 `ended` 尚无行为差异定义）、N5（离线 smoke + 产物级断言）。

## 已知限制

- **跨 Session 越权（A1）未收紧**：RPC 通道不暴露调用者 session 身份，同进程内其他会话只要知道会议 id，理论上可调用该会议的读写端点。现有防线是「会议归属 + 状态机」校验，不是身份校验。单人 / 单工作区无实际影响；多人共用同一 DSH 实例时请把它当作同一信任域。已在 README「已知限制」里明确标注。
- Host 侧并发写竞态（插件 stop/dispose 与文件写并发）仍暂缓；单进程内会议级写已由 `withMeetingLock` 串行化。
- `pnpm test` 使用 Node 标准测试运行器（每文件一个子进程）。在禁止子进程管道的环境（如 DSH 自带沙箱）会以 `spawn EPERM` 失败——那是环境限制而非测试失败，改用 `pnpm test:inline`（需 Node ≥ 22.8）。
